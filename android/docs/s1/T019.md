## 实现与安全边界

S0 基线中的两个 task 实际已经有 APK scanner / shell instrumentation / install 实现，README 中仍保留下一阶段预案。本轮将其接到 S1 真实数据与精确隔离 suite，不删除 S0 检查：

- `S1DebugSeed` 独占 debug source set；保留 S0 `DebugSeed` contributor、UUID/clock/version/10例测试。没有 Application 自动 seed、副作用启动参数或用户 UI 入口。
- 默认 S1 图只读冻结 factory 的 `finecoach.db`。新 seed 就写这份新库，并显式标记 dataset/version/scenario/status；不修改 factory/graph，不将普通业务页面改读另一个数据库。原先 README 的“向 S0 contributor 同步事务加行”预案不适合会切 dispatcher 的真实 Repository，已明确替换接线说明。
- 已有数据库先以 SQLite OPEN_READONLY 核对 schema与 ownership metadata，再允许 Room 打开。已有非seed（包括空库、v1旧库）、版本/场景不符、installing、不完整/损坏库均失败，不清库、不adopt、不迁移非seed。legacy回归断言 schema version仍1且原 metadata 保留。
- 首次写入 installing；业务数据经真实 StudentRepository/CreditUseCases/SessionRepository/ActiveSessionUseCases/FinishSessionUseCases/TemplateRepository 写入；所有业务写入各走既有事务，之后经真实 Repository 核验初始 inventory，最后在 metadata 事务中记录 rows/complete。中断会保留已落盘部分与 installing 并非零，不宣称成功；不自动续写或覆盖。跨进程 installer 使用独占 file lock，安装前显式停止目标进程。
- 完成后重装/重跑只验证持久标记与初始 rows，绝不再次插入或覆盖。教练编辑/删除 seed 行、结束训练或添加自己的行后仍保留；rows 明确是初始化 inventory，不伪装为当前行数。关库重开测试覆盖保留编辑/删除与不重复行。
- rows 实际 SQL 统计业务表 + S1自有metadata（含rows行），不计 Room/framework/generation/created_at；multi=66，single=55，empty=5。没有使用预期常数代替业务查询；测试与安装命令再固定精确计数。
- 只有原有固定数值 seed log（version/rows/status）；异常只返回固定失败状态，不输出业务字段、异常消息或原始系统日志。Release 扫描覆盖所有 APK entries 和 UTF-8/UTF-16LE/BE dex/manifest/resources 字节。

## 固定虚构场景

dataset=`fictional-s1-coach-core-v1`，version=1，clock=`2026-11-09T00:00:00Z`。学员 ID `72000000-0000-4000-8000-000000000001`～`...0007`；其他 ID 固定生成顺序1000起，分段/计划组800～933。所有人名、目标、电话、微信、备注、课包、动作与训练值均虚构。

| 场景 | 状态 | 初始计数/入口 |
|---|---|---|
| empty | 无学员/训练/模板 | rows=5，学员空态/新建 |
| single | 下列完整数据，仅学员1有进行中 | rows=55，Today 单 hero |
| multi（默认） | 下列完整数据，学员1/2各一进行中 | rows=66，Today 多 hero |
| 学员1/2 | 同名、不同ID，active；1无包，2可用包 | 列表/详情、跨学员训练与历史 |
| 学员3 | active、到期包（2026-11-02） | 到期显示、结束不自动扣 |
| 学员4 | active、耗尽包，真实手工 debit ledger | 0余额、流水 |
| 学员5 | active、ended 包 | 无当前包、历史包仍在 |
| 学员6 | active、旧ended + 新active 包 | 替换历史 |
| 学员7 | archived | 已归档/恢复 |
| 进行中训练 | 每课4动作：weightReps/reps/duration/cardio；有分段 | completed（重量）、pending（次数）、draft（时长/有氧） |
| 历史 | 学员2一节 completed，四mode均completed、公开/私密总结 | 真实完成、ad-hoc debit一次，余额7；历史与ledger |
| 模板 | 1模板/1分段/4动作，各1计划组 | 四mode；应用后pending |

single/multi 是首次安装的不同固定场景，不靠重置切换。默认multi可通过正常可见结束流程进入single/无进行中；真正无学员空列表由empty场景单独安装。切换场景须另选一份全新专用虚构 app 数据目录，任何清理由负责人另行批准；本轮不提供清库操作。未来切片 Appointment/身体数据/分享不造假入口。
