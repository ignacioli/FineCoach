## 与 iOS 的差异

- 列表不放资料库和设置。S1 没有对应路由，不能留只能点进空白的入口。
- 「今日 / 学员」默认不显示。调用方把 `showRootSwitch` 打开后，选「今日」只发 `S1Routes.TODAY`。接进主导航是 T016。
- 已归档列表没有单独路由，嵌在学员功能里。`S1Routes` 没有 archived 目的地。
- 空态没有吉祥物图。Android 主资源里没有这张图，本任务不新增图片。
- 列表副标题固定为「未设重点」。iOS 的重点来自预约；S2 才有预约。没有预约用例时，iOS 同样显示这句空文案。
- 详情不放下一节课、训练趋势、身体数据、导出档案，也不放删除流程里的「先备份」。这些属于 S2–S4，不能做成点了没页的入口。
- 最近训练行始终在，但本工作树没有 `HistoryRepository` 实现。没有传入该 port 时，行上不写「上完第一节课后会显示在这里」，点击发 `S1Routes.studentHistory`。即便以后传入历史记录，也不写「N 组」：`SessionHistoryRecord` 没有完成组数，本任务不新写查询。
- 删除确认不写「0 条已完成训练记录」。只有传入 `HistoryRepositoryPort` 且列表成功时才显示条数。
- 课包行始终在。传入 `CreditUseCases` 且没有有效课包时，显示「新建课包后，上完课会按课时扣减」。余额来自 T007，不在这里做课包页。
- 开始训练先调用已有的 `SessionRepository.startOrOpen`，成功后才发 `S1Routes.activeSession(sessionID)`。iOS 把学员 id 交给训练页再开课；Android 这条路由要求 session id。失败停在详情，不导航。
- 列表「继续训练」发的是已有 session id，不会再开一条。
- 「稍后添加」只离开新建页，不写学员。Android 没有 iOS 的完成引导用例，因此不会标记引导完成。
- 归档说明不再指向「更多」。永久删除的可见入口是编辑页上的「永久删除」。
- 编辑页「永久删除」的说明不再写「全部记录」。会删除的是学员和训练记录；课包与课时流水按已合入仓储和 S1-D05 保留。
- 归档和永久删除保持全屏，不改成 `FcConfirmationDialog`。依据是 iOS `DeleteStudentFlow.swift` 的既有全屏流程，S1-D15 记为例外。
- 标签加值的多行备注用无底色 `BasicTextField` 放在 `FcLabelValueRow` 里。`FcTextField` 是单行，且组件约定这种两栏不要再套一层输入框。
- `DS-HINT-BAR` 和单行 `DS-HERO-CARD` 已进入 Android roster。`DS-EMPTY-STATE` 仍是页面组合模式，空态留在学员 feature，不登记为共享组件。
