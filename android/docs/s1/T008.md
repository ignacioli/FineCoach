## 持久化边界

1. Repository 构造器显式接收 `expectedGeneration: UUID`；调用方在后台从当前库 `store_metadata[store_generation]` 取得绑定值。每次操作在 Room transaction 内重新比较；缺失或不符返回 `incompatibleInput`，不重新绑定旧 Repository。换库后必须重建 Repository/use case，并丢弃旧库的输入命令；不能把旧命令传给新 generation 的对象。
2. 所有 Repository 读写在 `Dispatchers.IO`。写入、子表替换、revision 检查和回读都位于 `runInTransaction`；成功只在 transaction 返回后发布。CAS 采用同一 SQLite transaction 内读取并精确比较 UInt64 revision，不按 TEXT 大小比较。
3. 同学员的开课查找、创建、focus 与 pointer 写入均在同一 transaction。现有合法进行中训练优先复用；新建才要求 Student active。缺失 pointer 可按现有 inProgress 行修复；重复 inProgress 行返回 `conflict`，不猜选一个。
4. Session / Template content 写入先转换到冻结 Domain、校验 owner、section membership、统一 orderIndex 与组字段，再按 owner 删除子行、重插候选内容。ID 或写入冲突中途失败会整体回滚；其他 owner 的行不属于删除范围。
5. Decimal 使用 `BigDecimal ↔ DecimalValue.fromBigDecimal(...).decimal`，不经过 Double；完成组通过 Domain 的完成校验。Domain 错误、非法映射、SQLite 错误均返回 `ApplicationResult.Failure`；取消协程继续抛 `CancellationException`；不返回 SQLite 消息，不写业务日志。
6. Template 应用在一个 transaction 中检查两个 expected revisions；复用冻结 `TrainingTemplate.applying` 生成新 section/exercise/set IDs，合并 trainingFocus，组为 pending。落盘 Session revision 增加一次；模板自身不修改。
7. `ActiveSessionUseCases` 保存状态按 Session 区分 Saving / Saved(revision) / Failed(error)。失败命令保留在该 use case 实例，`retry(id)` 重试原 expectedRevision；`complete` 在有待重试命令时拒绝。显式 command retry 也可用于调用方保留输入后的重试。实例应由调用方在工作流内持有；进程退出只承诺恢复已提交 Room 数据，不承诺恢复从未成功保存的内存输入。
8. 完成与放弃通过冻结 Domain finish gate，Session 状态与 pointer 释放同 transaction；`complete(settleCredits=true)` 明确返回 `incompatibleInput`，不声称已扣课。T009 使用完成与课包结算分别报告结果的流程，不能绕过失败保存状态检查。
9. SessionRepository 另接收绑定同一数据库的 ExerciseRepository。内容移除 sessionOnly 动作、完成或放弃时，在原 transaction 内调用 T006b 已有 `releaseSessionClaimsInTransaction`；ownerID 使用 SessionExerciseID，保留其他 owner 的 claim，并由该 helper 重算内置 claim。claim 释放失败也回滚 Session / pointer。

## iOS 对齐、差异与未决项

- 开课复用/归档条件对齐 `ios/FineCoachApp/Core/Application/ActiveSessionUseCases.swift:94-123`。
- stale pointer：`SessionManagedObject+Mapping.swift:233-249` 会忽略指向终态的 per-Student pointer，并回退查真实进行中训练；`ActiveSessionCoordinator.swift` 启动逻辑只恢复 active 数据。Android 同样不把终态恢复为进行中，不删 Session/组/分段；读取及启动时保留终态标量 pointer，仅显式开课时原子替换它。新建 pointer 仍由 `S1Dao.insert` 拒绝跨学员/非 inProgress 目标。legacy 字符串 `active` 不属于已冻结 Android v2 的 UUID key 合同，未扩 schema 支持它。

- 模板列表沿用 iOS updatedAtUTC 降序（`TemplateManagedObject+Mapping.swift:105-108`）；时间相同时增加稳定 ID tie-break。
- 模板整笔删除把 template-owned sections 与 exercises/planned sets 一起原子删除；iOS `CoreDataTemplateRepository.swift:100-117` 由调用方另外调用 section repository。业务删除范围相同，Android transaction 边界更集中，符合 plan。
