## 行为

- 新建、结束、手工扣减、手工返还都是可见按钮或可见行，不靠长按。
- 查询当前有效课包失败时 `ready` 保持 false，保存停用，并给出重试。失败不当作「没有课包」。
- 替换对话框把确认当时看到的课包 ID 传给 `createActivePackage`。`RequiresReconfirmation` 且仍有当前课包时，对话框改指向那个课包，不写入。当前课包已消失时显示「重新查看」并重新读取；不带着空 ID 和 `confirmReplaceActivePackage = true` 再保存。取消调用 `cancelPackageReplacement()`，零写入。
- 已过期或余额为 0 的有效课包，保存时由用例在同一事务结束旧包，不再弹第二层确认。
- 结束日期早于开始日期允许保存（S1-D02）。日期选择器用已有 `FcDatePickerDialog`；选中日按 UTC 午夜换算成 `LocalDate`，取消不改草稿。
- 调整原因用单行 `FcTextField`。余额不足由用例返回 `invalidState`，界面显示「扣减后余额将为负，检查课时数。」保存进行中按钮禁用，重复点击进不了第二次 `save`。

## 与 iOS 的差异

- 读取失败停用保存并提供重试（S1-D01）。iOS 把读取失败当成没有当前课包。
- 确认携带对话框里的课包 ID；不一致就再次确认，不静默结束。这是 Android 已定差异。
- 日期是 Material 3 对话框，按 UTC 日历日转换，不是 iOS 页内图形式日历。
- 调整原因是单行字段。iOS 是多行。设计系统 `FcTextField` 只有单行，没有另做多行组件。
- 编辑、确认、结束、手工调整没有单独路由。账本使用已有 `packages/{coursePackageID}`，学员 ID 留在 `PackageRouteHost`。
- 确认时看到的课包消失后，按钮文案是「重新查看」，不写入。
- 列表上的学员姓名只在调用方传入 `StudentUseCases` 且查找成功时出现。本任务测试没有传入。
- 手工扣减和返还没有二次确认（S1-D16）。与 iOS 一样，只有「保存调整」写入；页内返回和系统返回不写账本、不改余额。
