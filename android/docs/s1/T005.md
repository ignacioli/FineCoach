## 存储契约与边界

- UUID / Instant / LocalDate / BigDecimal 使用 S0 converters；Instant 保留纳秒，Decimal 用 canonical TEXT、不保留 scale。时间排序不能直接按变长 Instant TEXT 排序，DAO 本轮只对整数 order/position 排序；历史时间排序留 T009 按解析后的 Instant 实现。
- 私有 entity 的名称、可选文本和 StableExerciseID 使用 canonical String，构造/读取时调用冻结的 NormalizedName / ValidatedText / StableExerciseID parser 校验；不将 Room entity 暴露给 UI。相对 plan 表内的 value-class 写法，这是私有 Kotlin 表示差异，SQLite TEXT 和冻结的 record 字段完全可映射；不更改 wire format 或 Domain。
- Session 与 Template 的私有 `revision`（S1-D11）是经 `toULong()` 校验的 canonical decimal String，范围 0…18446744073709551615；避免 Room/JVM 的有符号整数截断。Repository 以 `Revision.value.toString()` / `Revision.parse()` 映射，CAS 只能做相等判断。Domain 的 Revision>0 规则仍由 Domain 执行。`orderIndex` / `position` 用 Long，entity 拒绝越过 UInt32 范围。
- enum 明确映射 wireValue 并调用 parse，未知 literal 失败；Boolean 转换仅接受 0/1，nullable Boolean 保持 null。focus 子表复合 PK 消除重复；planned sets 的 `(templateExerciseID, position)` PK 保持数组次序。
- DB UNIQUE：`credit_adjustments.sourceEventKey` 全局唯一；pointer 的 key 为 PK、sessionID UNIQUE；各 owner 内的 exercise/set/section order 为 UNIQUE。section 和 exercise 跨表共用 order axis，由 DAO 同一事务检查；sectionID 归属同时验证。重排与 disposition 的多行原子变更属于 T008。
- FK（全部 NO ACTION、无 CASCADE）：Student→Session→SessionExercise→TrainingSet；Package→Adjustment；Template→TemplateExercise→PlannedSet；Session/Template→各自 focus。多列索引/复合 PK 的左前缀覆盖 FK 查询。
- 不为 course_packages.studentID、active claim、pointer key/sessionID、section owner/sectionID、ledger linkedSessionID/linkedAppointmentID 或 catalog snapshot sourceID 添加 FK。ExercisePreference / ExerciseNameClaim 也保持 iOS 标量关联，不发明清理级联。Student 显式删除可保留 plan §3.4 列出的课包/ledger/claim/section/pointer 残留。T006a 负责实际删除事务与 archive identity key，不由本轮实施。
- `S1Dao.insert(pointer)` 先在 `@Transaction` 中读取 Session，验证同 Student 且 inProgress，再 ABORT insert；原始 insert 受 protected 限制。package claim 同样检查 package 同学员且 active。并发 start/reuse、状态终结与 pointer 释放、revision/generation 恢复、结算幂等仍属于 T007～009；本轮不冒充这些 Repository 行为已经完成。
- `store_generation` 是本轮明确命名的私有 metadata key，fresh factory 与 migration 共用初始化。`INSERT OR IGNORE` 不改已有 value；其余 metadata 包括 `created_at` 逐字保留。Room open-helper upgrade transaction 负责 DDL、generation、user_version 与验证失败的整体回滚。
- S2+ 仅保留 plan 指定的 appointmentID / linkedAppointmentID 与 enum literal；无 Appointment 表、预约功能、网络、权限、通知或 UI 变更。
