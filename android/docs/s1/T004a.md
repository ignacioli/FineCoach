## DomainError and ApplicationErrorCode

`DomainError` (`core/domain/training/DomainError.kt`) and `ApplicationErrorCode` (`core/application/ApplicationContracts.kt:45-59`) share these names: `emptyText`, `textTooLong`, `invalidDecimal`, `invalidNumber`, `invalidUnit`, `invalidMode`, `invalidState`, `invalidIdentifier`, `conflict`, `notFound`, `staleRevision`, `incompatibleInput`.

`ApplicationErrorCode.persistenceFailed` is only on the application contract. It is a storage failure, not a training-domain rule. T004a does not add a mapper: `core/application/**` is frozen. Later use-case tasks map `DomainException.error` onto `ApplicationErrorCode` by the same name, and use `persistenceFailed` for repository failures.

训练领域的文本错误已与学员领域及 iOS 对齐：

- `core/domain/training/DomainError.kt` 的 `parseDomainName(raw, field)` 是训练领域名称解析的共用入口，`Session.addingSessionOnlyExercise` 与 `ExerciseCatalogItem.make` 均调用它，错误字段分别为 `displayName`、`canonicalName`。该入口先调用 `ValidatedText.parse(raw, allowEmpty = true)`，将超长文本的 `IllegalArgumentException` 映射为 `DomainException(DomainError.textTooLong, field)`；规范化后为空则抛出 `DomainException(DomainError.emptyText, field)`，再构造 `NormalizedName`，不让这类异常从上述公开 API 逃逸。
- 这与 `ios/FineCoachApp/Core/Domain/ValidatedText.swift` 的 `emptyText` / `textTooLong` 规则一致，上限保持 `ValidatedText.maximumUTF8Bytes`（65536 UTF-8 字节）。备注入口接收已验证的 common `ValidatedText`，不解析原始字符串；common 本身不变。
- `DecimalValue.fromBigDecimal` 的规范十进制超过该字节上限时，仍抛出 `DomainError.textTooLong`。

## DecimalValue and port BigDecimal (T008)

`DecimalValue` stays the training-domain value. Its `decimal` property is a `java.math.BigDecimal`, and `RepositoryPorts` session/set records already store `BigDecimal` for the same fields (`elapsedSeconds`, weights, reps, duration, distance, speed, resistance). Mapping `DecimalValue` to and from those port fields is a **T008** repository handoff. This round does not change ports or `DecimalValue`'s arithmetic.

第 3 轮修复：`DecimalValue.seconds` 在转换为 `BigDecimal` 前拒绝 `NaN` 与正负 Infinity，抛出 `DomainException(DomainError.invalidDecimal)`，避免 `NumberFormatException` 逃逸；有限负数仍截为 0，有限非负数仍向下取整。依据是 `ios/FineCoachApp/Core/Domain/DecimalValue.swift:6-38` 的字符串及非数字校验均使用 `DomainError.invalidDecimal`；iOS `seconds` 本身（同文件 `seconds` 方法）没有明确的非有限值错误分支，因此 Android 沿用最贴近的现有 decimal 校验错误，不声称该边界与 iOS seconds 已有实现一致。`DecimalValue.parse` 原已将 `NaN`、Infinity 和无法解析的字符串映射为 `invalidDecimal`，本轮保留实现并补回归测试。

本轮移除 catalog `make` 直接调用 `NormalizedName.parse` 的旧描述，以及 Session 是原始名称“唯一入口”的旧描述；替换为实际的 `parseDomainName` 共用入口。数值变更仅收口非有限 seconds 的错误类型，保留正常转换与 arithmetic；未改 common、application、navigation 或 iOS。
