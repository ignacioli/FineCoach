## S1-D02（结束日早于开始日）

- 决策：照搬 iOS，**不校验** `endDate < startDate`（`CoursePackageEditorView.swift:161,183` 的 DatePicker 未限制范围；`CoursePackage` init 只校验课时 > 0）。
- Domain 实现：`CoursePackage` 没有日期顺序 `require`。
- 测试：`reverseDateRangeIsAllowedAndDateFactsStillUseEndDate` 用 `startDate=2026-02-01`、`endDate=2026-01-01` 构造成功，并验证：
  - `isExpired(2026-01-01) == false`（结束日当天不算过期）；
  - `isExpired(2026-01-02) == true`；
  - status 仍为 `active`；
  - `displayName` 仍使用开始日 `课包 · 2026-02-01`；
  - `cachingRemaining` 仍可刷新 cache。
- 边界说明：T003 只证明 Domain **接受该输入**；真实 Room 保存/读取由 T007 的 `PackageActivationTests`/`CreditRepositoryTests` 证明。本文件不把 Domain 构造写成已落盘。

## 对冻结接口的差额 / 待核实

1. **缺少共享 `ValidatedText` 值类型**（精确差额）
   - iOS：`ValidatedText` 负责 trim + NFC、非空、UTF-8 ≤ 64 KiB；`CoursePackage.name` 与 `CreditAdjustment.reasonText` 都使用它（`ValidatedText.swift:3-21`、`CoursePackage.swift:22`、`CreditLedger.swift:43`）。
   - Android 冻结 `common` 没有该类型。T003 暂用 `String?`：
     - `manualCorrection` 只检查 `reasonText` 非空白（与 iOS 的必填语义一致）；
     - 课包名不强制 trim/NFC/64 KiB；空白名由 `displayName` 回退处理。
   - 影响：T002/T005/T007 若各自实现文本校验会分叉；建议由 `common` owner 决定是否冻结共享 `ValidatedText`，或在 T005/T007 统一收敛。T003 未改冻结文件。
2. **缺少共享 Domain 错误类型/稳定错误码**（精确差额）
   - T003 使用 Kotlin 原生 `IllegalArgumentException`（非法值）与 `IllegalStateException`（非法状态转换），与 T001 对 ID 的 `IllegalArgumentException` 策略一致。
   - iOS 抛 `DomainError`（`.invalidNumber`、`.invalidState`、`.emptyText`）。T007 需要把上述异常映射到 `ApplicationErrorCode`；目前没有共享映射约定。
3. **`AppointmentID` 未冻结**
   - `CreditAdjustment.linkedAppointmentID` 使用 `String?`（`RepositoryPorts.CreditAdjustmentRecord` 同样如此）；`CreditLedgerSourceEventKeyFactory.appointmentAbsent(String)` 会先 `UUID.fromString` 规范化再大写。
   - S1 不建 Appointment 功能；S2 若启用应冻结 `AppointmentID`。
4. **`CoursePackage` 与 `CoursePackageRecord` 字段结构重复**
   - Domain 值在 `core/domain/credit`；冻结 port record 在 `core/application/RepositoryPorts.kt`。T007 负责双向映射，并须在写入后以 ledger 重算 cache（`RepositoryPorts.kt:54-65`、plan.md:79）。
   - 本轮未让 Domain 反向依赖 `core/application`（符合 S1-D07）。
5. **未验证项**
   - 按指令未运行 Gradle；宿主正式命令见下。
   - 未证明 Room 保存/读取、唯一 `sourceEventKey` 约束、事务内余额检查与并发；这些属于 T005/T007/T009。
   - 未证明 D01 的“确认时旧包变化 → 重新确认且零写入”；属于 T007。
