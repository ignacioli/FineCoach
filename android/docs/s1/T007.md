## 4. S1-D01 平台有意差异与 iOS 同缺口待办登记

依据 `.handoff/decisions/android-port.md` **S1-D01** 与 `spec.md` §5：

1. **Android 额外保护（已由 `PackageActivationTests` 证明）**：
   - **保护 1（查询失败禁保存）**：新建课包前查询当前有效课包或账本失败时，返回 `ApplicationResult.Failure(ApplicationErrorCode.persistenceFailed)`，禁止保存并提示重试，绝不降级当作“当前无有效课包”。
   - **保护 2（保存事务内重验确认对象）**：保存命令携带 `observedActivePackageID`；在 Room 写入事务内重新读取 `active_package_claims` 与实时账本余额。若当前有效课包需确认但未确认、仅传 `confirmReplaceActivePackage = true` 却未携带匹配的 `observedActivePackageID`、或确认期间当前有效课包已变为其他课包/已结束，一律返回 `SaveCoursePackageResult.RequiresReconfirmation(currentActivePackage)`，事务内零写入。
2. **iOS 同缺口待办（不要求未修复的 iOS 同结果，本轮不改 iOS 产品代码）**：
   - **待办位置 1**：`ios/FineCoachApp/Features/CoursePackages/CoursePackageEditorView.swift:45-53` — `loadExistingActivePackage()` 使用 `try? await useCases.activePackage(...)` 和 `try? await useCases.balance(...)`；当底层读取失败时，`existingActivePackage` 保持 `nil` 或回退到缓存值，随后点击保存会跳过确认直接调用 `createActivePackage` 静默结束原有效课包。
   - **待办位置 2**：`ios/FineCoachApp/Core/Application/CreditLedgerUseCases.swift:30-53` 与 `ios/FineCoachApp/Core/Persistence/CoreDataCoursePackageRepository.swift:30-72` — `activatePackage` 未接收确认时观察到的旧课包 ID，事务内无条件结束当前 `existingClaim` 指向的课包；若确认前后有效课包发生变化，旧确认仍会静默结束新课包。

## 5. 测试类与预期用例数

### 5.1 `com.ignacioli.finecoach.PackageActivationTests`（预期 **15** 个 `@Test`）

1. `createFirstActivePackagePersistsAndSurvivesCloseAndReopen`：无旧包时直接新建，关库重开并重建 Repository/UseCase 后保持 active 与完整字段。
2. `existingUnexpiredNonZeroActivePackageRequiresConfirmationAndCancelLeavesZeroChanges`：存在未过期且余额 > 0 的有效包时需确认；未确认返回 `RequiresReconfirmation` 且零写入；取消确认零变更。
3. `confirmedReplacementAtomicallyEndsOldPackageAndActivatesNewOneAcrossReopen`：明确确认后原子结束旧包并激活新包，同学员 `active <= 1`，关库重开后状态与余额一致。
4. `booleanConfirmWithoutMatchingObservedPackageIDCannotBypassConfirmationGate`：仅传 `confirmReplaceActivePackage = true` 但无匹配 `observedActivePackageID` 时拒绝绕过，返回 `RequiresReconfirmation` 且零写入。
5. `samePackageIdCannotOverwriteExistingActiveOrEndedPackageOrBypassConfirmationGate`：传入当前有效包或历史已结束包的同一 `coursePackageID` 时，未确认先被确认门禁拦截，确认后也被拒绝改写（返回 `conflict` 且零写入，FR-009）。
6. `activePackageDriftAfterConfirmationPromptRequiresReconfirmationWithZeroWrites`：确认前旧包已被替换为另一有效包，提交旧确认返回 `RequiresReconfirmation(新包)` 且零写入（D01）。
7. `activePackageEndedBeforeStaleConfirmationRequiresReconfirmationWithNullActive`：确认前旧包已结束，提交旧确认返回 `RequiresReconfirmation(null)` 且零写入（D01）。
8. `activePackageAppearingAfterNullObservationRequiresReconfirmationEvenForExpiredOrDepleted`：初始观察为“无有效包”（`observedActivePackageID == null`），保存事务内发现已存在有效包（即使已过期或余额为 0）时，返回 `RequiresReconfirmation` 且零写入（D01）。
9. `localTimeZoneDayBoundaryRequiresConfirmationWhenUtcHasAlreadyCrossedMidnight`：注入非 UTC 时区，验证 UTC 已跨日但本地日历日尚未过期时仍要求确认，不因 UTC 提前跨日静默结束旧包。
10. `activePackageLookupFailureForbidsSaveAndReturnsRetryableErrorWithZeroWrites`：查询当前有效课包失败时禁止保存并返回 `persistenceFailed`，底层数据库零写入且无重复预读（D01）。
11. `expiredExistingActivePackageSavesAndEndsOldPackageWithoutExtraConfirmation`：旧包已过期（`today > endDate`）时读取不自动结束，新建时无需额外确认直接保存并结束旧包。
12. `zeroBalanceExistingActivePackageSavesAndEndsOldPackageWithoutExtraConfirmation`：旧包账本余额为 0 时读取不自动结束，新建时无需额外确认直接保存并结束旧包。
13. `reverseDatesWhereEndDatePrecedesStartDateAreSavedVerbatimPerD02`：结束日早于开始日照 iOS 原样保存并在关库重开后保持（D02）。
14. `failedReplacementTransactionViaSqliteTriggerRollsBackOldPackageStatusAndClaim`：通过 SQLite `BEFORE INSERT ON course_packages` trigger 注入写失败，验证旧包状态、claim 与流水在内存及关库重开后均完整回滚。
15. `explicitEndPackageRetainsHistoryReleasesClaimAndRejectsDoubleEnd`：显式结束 active 课包保留历史并释放 claim，重复结束返回 `invalidState`。

### 5.2 `com.ignacioli.finecoach.CreditRepositoryTests`（预期 **8** 个 `@Test`）

1. `manualDebitAndCreditUpdateBalanceAndTrailAndSurviveCloseAndReopen`：手工扣减与返还真实落盘、更新余额与缓存，关库重开并重建对象后流水与余额一致。
2. `manualCorrectionValidatesPositiveAmountAndNonBlankReasonWithoutWrites`：0/负数课时、空白原因、超 64 KiB 原因分别返回 `invalidNumber`、`emptyText`、`textTooLong`，零写入。

## 6. 第 1 轮修复记录（Robolectric 主线程 Room 查询拒绝）

- **现象**：第 1 轮宿主运行中，`PackageActivationTests`（13 个）与 `CreditRepositoryTests`（8 个）首次调用 `loadCreationContext` / `createActivePackage` 时均返回 `ApplicationResult.Failure(persistenceFailed)`。
- **静态追踪与根因**：
  1. `CoursePackageEntity` 与 `ActivePackageClaimEntity` 对 `students` 无外键约束（标量引用），无需前置插入 `StudentEntity`。
  2. `FineCoachDatabaseFactory.create(context)` 按 `plan.md:42`（“阻塞 DAO 在后台执行，不允许 main-thread queries”）未启用 `allowMainThreadQueries()`。
  3. 第 1 轮测试在 `openFreshStack()` 中将 `CoursePackageRepository` 的 `ioContext` 覆盖为 `Dispatchers.Unconfined`，并直接在 Robolectric `@Test` 方法（运行于 Android 主线程）内调用 `runBlocking { ... }`。
  4. 当 DAO 在主线程执行首次查询 `s1Dao.findActivePackageClaim` 时，Room `assertNotMainThread()` 抛出 `IllegalStateException("Cannot access database on the main thread...")`，被 `CoursePackageRepository.runStorage` 捕获并映射为 `ApplicationResult.Failure(persistenceFailed)`。
- **修复**：
  1. `PackageActivationTests` 与 `CreditRepositoryTests` 移除 `ioContext = Dispatchers.Unconfined` 覆盖，保持 `CoursePackageRepository` 默认的后台 `Dispatchers.IO`；同时参照 `S1EntityRoundtripTests` / `RoomSkeletonTests` 使用单线程 `worker` 的 `offMain { ... }` 执行测试体与 `database.close()`。
  2. 将两处 SQLite 故障注入触发器从 `CREATE TEMP TRIGGER` 改为 `CREATE TRIGGER`，确保跨 SQLite 连接生效。
  3. 将测试中的 `as ApplicationResult.Success` / `as ApplicationResult.Failure` 强转全部替换为 `requireSuccess` / `requireFailure` / `requireSaved` / `requireReconfirmation` 断言辅助函数，失败时在 `AssertionError` 消息中仅输出 `error.code`（不输出任何业务数据）。

## 7. 第 2 轮修复记录（Codex 独立复核 5 项条件）

| 编号 | 复核条件 | 处理方式 |
|---|---|---|
| 1 | **同 ID 改写绕过门禁（FR-009）**：`CoursePackageRepository.save` 原先在确认门禁前允许 `activeUUID == targetUUID` 原地改写总课时/日期 | 删除 `activeUUID == targetUUID` 的原地改写分支；先执行 `observedActivePackageID` 重验与确认门禁，并在结束旧包前校验 `s1Dao.findCoursePackage(targetUUID) == null`，任何复用有效包或历史已结束包 ID 的保存请求均返回 `ApplicationErrorCode.conflict(field = "coursePackageID")` 且零写入。新增 `samePackageIdCannotOverwriteExistingActiveOrEndedPackageOrBypassConfirmationGate` 测试。 |
| 2 | **null 观察漂移**：`observedActivePackageID == null` 而事务内发现已有有效包（含已过期或 0 余额）时，必须返回 `RequiresReconfirmation` 且零写入 | 在 `CoursePackageRepository.save` 中当 `activePair != null` 时，无条件先判 `if (command.observedActivePackageID != activeDomain.coursePackageID)` 返回 `RequiresReconfirmation(activeDomain.toRecord())`（涵盖 `observedActivePackageID == null`）。更新 `activePackageAppearingAfterNullObservationRequiresReconfirmationEvenForExpiredOrDepleted` 直接验证 `observedActivePackageID == null` 面对并发零余额有效包和并发已过期有效包时均返回 `RequiresReconfirmation` 且零写入。 |
| 3 | **日期边界时区**：默认使用 UTC 会使 UTC 提前跨日时把本地尚未过期的课包误判为已过期 | `CoursePackageRepository` 与 `CreditUseCases` 的 `zoneID` 默认值改为 `ZoneId.systemDefault()`（保持可注入）。测试套件默认注入非 UTC 时区 `Asia/Shanghai`，并新增 `localTimeZoneDayBoundaryRequiresConfirmationWhenUtcHasAlreadyCrossedMidnight` 覆盖 UTC 已跨日而本地未过期时必须要求确认、以及 `Asia/Shanghai` 本地午夜跨日前后的确认判定边界。 |
| 4 | **缓存断言**：`CreditRepositoryTests` 需直接断言 `course_packages` 表持久化的 `remainingCreditsCache` 列与账本汇总一致 | 在 `CreditRepositoryTests` 新增 `rawPersistedRemainingCreditsCache` 直接通过 `database.s1Dao().findCoursePackage(...)` 读取数据库行的 `remainingCreditsCache` 列，并在成功写入、失败回滚（同时覆盖 `BEFORE UPDATE` 与 `AFTER UPDATE` 触发器回滚）以及关库重开后逐一断言其与 `useCases.balance(...)` 账本汇总一致。 |
| 5 | **冗余清理**：删除 `CoursePackageRepository` 3 个无调用方法，合并 `CreditUseCases` 重复预读 | 删除 `CoursePackageRepository` 中未使用的 `findPackage`、`adjustmentsForPackage`、`balanceForPackage`；`CreditUseCases.createActivePackage` 直接委托 `savePackage` 单次预读，`createPackageWithContext` 复用已加载的 `contextResult` 不再重复调用 `repository.active`，同时在 `activePackageLookupFailureForbidsSaveAndReturnsRetryableErrorWithZeroWrites` 中断言 `activeCallCount` 无重复预读。 |
