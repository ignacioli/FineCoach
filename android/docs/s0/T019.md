# T019 组件截图框架

范围：复用 T003 的 Roborazzi 1.77.0 / Robolectric 4.17、API36 NATIVE renderer 和 AGP resource-aware test classpath。新增 `ComponentScreenshotTests`，代表对象是 T016 debug catalog 的 `DS-BUTTON/default`。随包 Noto Sans SC、zh-CN、fontScale=1、density=2；组件 capture 390×160dp，无动画，Compose clock 手动推进一帧。独立基线位置 `android/screenshot-baselines/components/DS-BUTTON-default.png`；本轮不创建该目录或文件。

从 `android/` 执行 `./gradlew :app:s0G5`。任务只 verify，不依赖插件 restore，不接受 record=true；每次实际执行，独立 XML/HTML，finalizer 拒绝失败/skip/0 tests/错误 suite/count。运行前后对全部 baseline 文件取 SHA-256，任何变化非零。缺基线由测试明确抛出 `Missing owner-approved component baseline ...; never auto-record`，不是自动 record。

负责人专用 record 命令见 `android/README.md` 的独立段落；agent 禁止执行。当前没有负责人批准的组件基线，G5 保持 BLOCKED，不把框架完成写成 G5 验收。

## S0-13 接口

产品根运行：

```sh
node android/scripts/baseline-guard.mjs "$PWD" <approved-base-commit> [trusted-approval-commit] [before-json]
node --test android/scripts/baseline-guard.test.mjs
```

必须由宿主明确传入批准的比较基点，不能自动使用 HEAD。stdout 为 JSON：committed/staged/unstaged/untracked 各自文件清单、HEAD/baseCommit、全部基线与批准记录的 manifest/digest、stable/unapproved/status。运行前保存 stdout；运行后用第四参数传入该 JSON。`BASELINE_CHANGED` 返回 1；基点无效直接失败。

监测 `android/screenshot-baselines/` 与 `android/design-assets/baseline-approvals.json`，包括删除。批准记录从宿主明确传入的 trusted approval commit 读取；记录引用此前的 baseCommit 和 approvedCommit，不要求 commit 内容自引用。两个 commit 必须是 trusted approval commit 的祖先，approvedCommit 也是 HEAD 的祖先，之后不能再有未批准的 baseline commit 变化。工作树内新写的批准文字不可信；无有效批准记录的任何变更失败。记录文件 fields 为 baseCommit、approvedCommit、files（相对路径→SHA-256，删除写 DELETED）。只有宿主决定受信 commit；这不是技术权限隔离。无批准而仅比较前后 snapshot 时第三参数传 `-`。本轮不创建批准记录。S0-13 仍需集成 host gate 的前后调用、负责人批准流程与 checkpoint 复核，不能据此宣称 host gate 已接入。

受控测试只在独立临时 Git repository 制造 staged/unstaged/untracked/committed 情形，不 stage/commit 产品仓；四种变化全部拒绝，前后 digest 变化也拒绝。测试结果见本文末尾执行记录。
