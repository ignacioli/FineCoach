# T043 关联训练完成不再出现临时课扣课选择

分类与依据：D。FR-009 / S1-FR-036。iOS `ActiveSessionViewModel` 注明 appointment-linked debits need no prompt；`FinishSessionUseCases.settlement` 对关联训练在课包可用时直接 `debitOnSessionComplete`，临时课仍返回 `AdhocChoiceRequired`。
影响范围：`FinishSessionScreen` / `FinishSessionUiState`。不改 `skipDebit`：关联训练调用它会 `invalidState`。S1 结束流程测试保持原断言。
设计决定：无新视觉决定。关联完成不画「扣 / 不扣」。课包不可用时结算仍是 `PackageUnusable`，且关联训练不能走 `skipDebit`；界面因此不提供会失败的「不扣课」。这条出口是否应另给可见收尾，留给负责人。
实施与验证：`LinkedFinishEntryLayoutTests` 真实点击丢弃、重试、返回继续；断言没有 `finish-credit-accept` / `finish-skip`，Room 里安排变为 completed，且只有一笔 `sessionComplete`。`FinishSessionEntryLayoutTests` 仍点击临时课的扣课确认。入口行在 `implementation-map.md`。
结果：完整 unit 含这两类为绿（见阶段报告的 184635 日志，1133/0）。不宣称设备或人眼验收。

iOS delta：完成路径与 iOS「关联安排不弹扣课选择」一致。扣课写入失败时 Android 只留重试，不提供「不扣课」，因为 `skipDebit` 对关联训练拒绝。iOS 的 unusable 对话框仍有 skip / adjust。
