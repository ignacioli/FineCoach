# T021 系统重排

实现 `ReminderRescheduleReceiver`：仅接受 BOOT_COMPLETED、TIME_SET、TIMEZONE_CHANGED、ACTION_SCHEDULE_EXACT_ALARM_PERMISSION_STATE_CHANGED 与显式私有提醒投递。`exported=false`，系统广播仍可达；异步使用 goAsync，在 finally finish。通过同一 S1Runtime graph 与 Room 对账，系统事件 force=true，弥补 OS 闹钟丢失或授权变化。启动/前台恢复也强制重排。已过提醒时刻不补发。

测试：`AppointmentReminderTests.forcedReconcileRestoresLostAlarmsAndUsesNewTimeZone`、`exactAccessChangeReplacesWindowWithIdleExactAlarm`；固定 DST 时刻。JVM 验证对账入口；续跑 2 新增 TIME_SET 的 Context.sendBroadcast → ReminderRescheduleReceiver.onReceive → goAsync/finish → OS alarm 恢复链路测试。真实设备系统广播及重启后的 OS 行为未验证，留 SC-004 设备门禁。

最终自测见 T023；本任务不代表设备验收。

## 续跑 2（2026-11-18）

启动四路触发改为 recovery 成功后的一次 IO 强制对账；invalidation flow 用 emitInitialState=false、conflate，权限初值不发请求，前台恢复只在真正 stop→resume 发请求。请求通过单个 conflated channel 串行消费，运行中至多保留一个待处理请求。测试的 MIME 仅用于隔离动态注册 receiver 与 Manifest 的并行投递，不改变产品 receiver。真实广播链路测试通过（AppointmentReminderTests 全类 12/0/0/0）；结果见 T023。
