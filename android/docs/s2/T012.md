# T012 Room v2 → v3

## 续跑 5：S2-D07 删除语义

S1 现状：`StudentRepository.delete` 删除训练的 sets/exercises/focus、sessions、两种大小写 archive identity key 和 Student；**不删除或修改 course_packages、active_package_claims、credit_adjustments**。这些标量引用可保留历史 UUID（`S1Entities.kt:45-111`），现有 `StudentRepositoryTests.successfulDeletionChecksEveryTableAndPreservesOtherStudentAndScalarResidue` 明确断言保留行内容。原放弃空训练保留 abandonedEmpty Session 行，不是物理 DELETE；本轮不改变这个 S1 行为。

依据 S2-D07 / FR-007b：

- `storage/repository/StudentRepository.kt:56-73`：原 StudentDeletionPolicy 的进行中拦截与显示名确认之后，在同一个 Room transaction 内删除该学员全部 appointments、再删除 recurrence_series，然后执行原训练/学员删除。没有新增用户前置拒绝；其他学员安排不动。
- `storage/dao/T006aStudentDao.kt:20-24`：增加按 studentID 删除安排和系列的 DAO；没有课包/ledger DELETE 或金额 UPDATE。
- `storage/entity/AppointmentEntity.kt:21` 与 `storage/migration/Migration2To3.kt:25`：linkedSessionID 外键改为 ON DELETE SET NULL，任意真正 DELETE sessions 的路径都会解除链接；不改安排状态。正常放弃仍由既有 abandonLinkedAppointment 恢复 scheduled 并清链接（其余 Session 生命周期不变）。studentID / seriesID 外键保留 NO ACTION，选择显式事务顺序而非扩大级联。
- `storage/migration/Migration2To3.kt:32,44-48`：appointments_restrict_delete 仍拦截 session 或 ledger 引用，仅当 store_metadata 的内部 `s2.deletingStudent` 值等于该安排 studentID 时例外。StudentRepository 在通过原删除 policy 后插入此标记，完成删除后清除；同事务异常/崩溃全部 rollback，其他连接不可见中间标记。这样只为当前学员的授权清理放行，不解除 deleteFuture 的保护，也不让另一学员共用放行。ledger 的 linkedAppointmentID 作为历史 UUID 原样保留；新写 ledger/session 引用的原有触发器不变。
- fresh callback 和 Migration2To3 都调用同一 installAppointmentIntegrity，外键与实体同步；`3.json` 由 Room KSP 重新导出，未手改，1.json/2.json 不变，无 destructive fallback。该 schema v3 尚在 Phase 2，迁移证明范围仍为 v2→v3 / fresh，不新增版本迁移。

**Phase 3 交接：提醒对账必须撤销所有已删除安排的闹钟；本轮不写调度代码。**

用例回归覆盖：周期未来安排、已完成关联训练及 sessionComplete + appointmentAbsent 两条实际扣课 ledger；删除学员后安排/系列为 0，训练和学员删除，课包/claim 完整行不变、ledger 金额与历史 appointment UUID 不变，其他学员安排保留；临时删除标记不残留。deleteFuture 对仍被 Session 或 ledger 引用的未来安排分别失败且全表行不变。migrated 库测试重新建立已完成 Session 的双向关联后删除学员成功；fresh/migrated 库实际 DELETE Session 都清空 linkedSessionID。S1 原放弃恢复与 policy / 删除回滚测试均保留。

## 实现与取舍

新增 `appointments` 和 `recurrence_series`，显式 `MIGRATION_2_3`，Room KSP 生成 `3.json`。`1.json`、`2.json` 未修改；无 destructive fallback。Appointment 的 16 个字段均独立落盘（trainingFocus 以稳定 enum name 集合编码）；series 的终止条件 endDate / repeatCount 二选一由 domain 与 mapper 验证，重开后恢复。

新表建立 student / series / linkedSession 外键和查询索引。S1 `sessions.appointmentID` 与 `credit_adjustments.linkedAppointmentID` 不改名、不重建表：migration 与 fresh-create callback 安装 INSERT/UPDATE 引用检查和被引用 Appointment 的 DELETE 限制 triggers。旧表原有行不被重写，避免历史引用导致整库迁移失败；历史 dangling reference 不做静默删除或修复，后续新引用必须存在。相较 plan「补外键语义」，这里用 triggers 而非重建 S1 表，保留证据在迁移测试。
