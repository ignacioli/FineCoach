# S2-D22 本次及以后只重发被替换的日期

负责人 2026-11-19 批准，仅 Android。`AppointmentRepository.editFuture` 不再从边界按原 termination 调用 `materializedDates`。

## 行为

`FutureAppointmentEdit` 仍只改时间、时长、提醒和边界当次的训练重点，不改日期、间隔，也不通过该输入改终止条件。

被 `superseded` 覆盖的安排（边界及以后、`scheduled`、未脱离）按各自原日期重发，不多不少：

- 新实例日期等于 `superseded` 的日期。
- 已完成、已取消、缺席、进行中、已脱离的日期保留原行，不另建 `scheduled`。
- 先前 `deleteFuture` 去掉的日期不回来。
- 新系列的 `EndDate` 不变。`RepeatCount` 改为 `RepeatCount(superseded.size)`，下一次「本次及以后」按实际剩余行计数。
- 事务、冲突检查（排除 `superseded`）、旧系列标为 `ended`、逐次 focus 与边界 focus、`afterReminderChange`，以及边界必须已有 `scheduled` 实例，保持原样。

这替换 T013 里「从 boundary 按原 count 重新展开」的 Android 行为。T013 文件本轮不改。

## 与 iOS 的差异

iOS `AppointmentUseCases.applyThisAndFuture`（`ios/FineCoachApp/Core/Application/AppointmentUseCases.swift:361-390`）仍把原 termination 交给 `materializedDates`，从边界再展开。因此 `RepeatCount` 会从边界再计一次，并在已取消、缺席、已完成、进行中或已脱离的日期上再造 `scheduled`。iOS 冻结，留到 S2-D15 批次。Android 从本决定起不再跟随这一段。

共享向量 `s2-this-and-future` 只断言 past / detached / resolved、旧系列 ended，以及重发结果前两条的时间与 focus。该场景下新行为的前两条仍是边界（thighs、11:30）和下一节未脱离实例（back、11:30）。向量未改。
