## 5. spec 符合性

M1A-FR-001：「首次启动 MUST 在创建第一名 Student 前说明数据默认留在本机和分享最少披露边界；MUST NOT 要求注册或登录。」AC-001：「Coach 阅读本机/最少披露说明，跳过首次创建……」

- **只留一个链接、页面上不写这两项事实**：用户不点链接就看不到说明，「MUST 说明」变成了「可以去看说明」，不满足 M1A-FR-001 的字面要求。这种做法需要先修订 M1A-FR-001，本设计不采用。
- **方案 B r2（本设计）**：两项事实以要点标题常驻页面——「资料只在这台手机」（本机保存）、「私人信息不会分享出去」（最少披露边界）；链接只承载完整清单和背景。页面在创建第一名学员之前已经「说明」了两项事实，满足 M1A-FR-001 与 AC-001，不需要修改 spec。
- r2 删除小字后，原第 3 条标题「分享内容由你挑选」只说了「由谁挑选」，没有说出边界（有些信息永远不分享）——单看标题，最少披露边界要点开链接才知道，会退回到上一条的「只留链接」情形。所以把标题改为「私人信息不会分享出去」，直接陈述边界；「由你挑选」移到面板。这是为保持合规做的文案选择，请产品负责人确认（§8）。
- 「不用注册登录」不再出现在主页面（移入面板第 2 行）。M1A-FR-001 对注册登录的要求是「MUST NOT 要求」，是行为约束而不是说明义务；页面本身没有任何注册登录入口，满足该要求。
- 「私人信息」是概括说法，完整的永久禁止字段在 W-02 列出。判断：M1A-FR-001 要求说明的是「边界存在」，字段的完整清单由 M1A-FR-037 约束分享报告本身；现状页面同样只列了部分字段。
- M2-FR-025：选择「Coach 使用」后仍进入「M1 既有的 Coach 首次说明与主流程」——本页角色不变，只改呈现。
- M1A-FR-002：「稍后再添加」保留可见的跳过入口，行为不变。

## 10. 入场动画评估（产品负责人 2026-10-10 请 Agent 评估）

**结论：做，但只做一次、克制的「依次淡入上浮」，不做插画动画或页面级过场。**

依据项目调性：设计系统是「暖炭黑素雅」（README）——无阴影、无饱和色、层级靠字号和留白；现有界面没有装饰性动画。欢迎页只出现一次，是产品第一印象，一点节奏感能让三条要点「被读到」，而不是一眼扫过；但弹跳、缩放、吉祥物摇摆、Lottie 都与素雅调性不符，Lottie 还违反「只用 Apple 框架」。

| 元素 | 动画 | 延迟 | 时长 / 曲线 |
|---|---|---|---|
| 吉祥物头像 + 标题 + 副标题 | 透明度 0 → 1，向上 8pt 回位 | 0 | 0.35 s，easeOut |
| 要点 1 / 2 / 3 | 同上，逐行 | 0.25 / 0.35 / 0.45 s | 0.35 s，easeOut |
| 链接 | 透明度 0 → 1 | 0.55 s | 0.25 s |
| 底部主按钮、「稍后再添加」 | **不做动画**，首帧就可见可点 | — | — |

规则：
- 只在本页第一次出现时播放；从 W-02 面板关闭、从新建学员返回时不重播（`@State` 标记已播放）。全部结束 < 1 s，不阻塞任何操作。
- 位移只用 `space.2` 8pt，不缩放、不弹簧、不循环；图标不单独做 symbol effect。
- 系统「减少动态效果」打开时：不位移，只做整页 0.2 s 淡入（或直接显示）。
- VoiceOver 不受影响：元素从首帧起就在无障碍树中，动画只改视觉透明度和位移。
- 实现：SwiftUI `opacity` + `offset` + `withAnimation(.easeOut(duration:).delay(_:))`；时长与延迟属于动画参数，不是设计 token，不触发 `DesignValueScanTests` 的原始值规则（若扫描误报，在组件内集中定义一处常量）。
- 「让它显示得更自然」的静态部分已在 r2 处理：去掉小字后每行只有一个短标题，行距放大到 52，内容块整体下移居中，避免上半屏拥挤、下半屏空。
